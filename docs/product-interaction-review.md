# TTerm 产品与交互问题评审表

## 使用方式

这份文档用于在动工前逐项确认方向，不代表所有条目都必须实现。

请在每一项的“你的决定”中填写 `接受`、`修改`、`暂缓` 或 `拒绝`，并在“你的批注”中补充判断。确认后的条目再拆分为设计与开发任务。

优先级含义：

- **P0**：影响核心价值、安全边界或首次成功体验；
- **P1**：明显影响高频工作流和长期使用效率；
- **P2**：影响完整度、可访问性或后续扩展。

## 09. 会话关闭保护

### PD-26｜建立统一的 Session Close Guard

- **优先级**：P1
- **现状/问题**：标签关闭、`Ctrl+W`、右键关闭、关闭其他标签、关闭窗口和退出应用都可能结束仍在运行的 Agent、远程任务或设备会话。如果只保护某一个入口，相同动作会产生不同风险语义；如果每次关闭都确认，又会形成持续打扰。
- **建议**：所有关闭入口统一经过 `requestClose` 与 `evaluateCloseRisk`。仅在可能造成实际损失时确认：Local 优先依据前台进程树判断是否存在 Shell 之外的子进程；SSH 无法可靠识别远端任务，连接中默认视为有风险，断开后直接关闭；Serial 的活动连接策略单独评审。不要使用 CPU 占用、最近输出或静默时长判断任务是否空闲。
- **交互文案原则**：说明即将失去的具体对象和结果，例如“此终端仍有进程正在运行，关闭将终止这些进程”或“SSH 会话仍处于连接状态，关闭将断开远程连接”。主要动作使用“关闭终端”或“断开并关闭”，避免含糊的“确定”。
- **长期设置方向**：评估“仅有运行任务时提醒（推荐）/ 所有活动连接都提醒 / 从不提醒”，但第一版不一定开放设置。
- **验收标准**：所有关闭入口获得一致判断；空闲 Local Shell 可直接关闭；Local 子进程、连接中的 SSH 获得对应确认；取消后会话和焦点保持不变；批量关闭能够汇总风险，避免连续弹出多个确认框。
