# ESP32 AT ↔ TCP — 设计、测试、验收

两件程序：**设备固件**与**对端 TCP 服务**。实现不在本文仓库。本文是唯一依据。

设备先处于 **AT 模式**。用 AT 配置 Wi‑Fi 与对端地址后，`AT+CONNECT` 连上指定主机的 TCP（telnet 语义：双向裸字节）。进入 **数据模式** 直至**对端断开**，再回到 AT 模式。不用 `AT+CIPSTART` 建连。

---

## 1. 范围

```
主机（串口） ←UART→  ESP32
                    AT 模式：解析命令
                    数据模式：UART ↔ TCP 裸转发
                         │
                         ▼
              已配置的 IPv4:port（telnet 式 TCP）
```

- 对端是普通 TCP 流（与 telnet 相同：连上即可收发字节，无 HTTP）。
- 对端地址**只能**由 AT 写入，不依赖烧录死的主机/端口。
- 设备不得把 `127.0.0.1` 当作对端（那是板子回环）。对端必须是服务机的局域网 IPv4（或其它设备可达地址）。
- 不是乐鑫完整 AT。未规定命令 → `ERROR`。
- 不测：SSL、多连接、`AT+CIPSEND`、本地 `+++` 逃逸、`AT+CIPSTART`。

---

## 2. 模式

| 模式 | UART 含义 | 进入 | 离开 |
| --- | --- | --- | --- |
| AT | 一行一条命令 | 上电；数据模式因**对端断联**结束 | `AT+CONNECT` 成功 |
| 数据 | 每一字节转发到 TCP；TCP 每一字节写出 UART | `AT+CONNECT` 成功之后 | 对端关闭 TCP（或链路掉死） |

数据模式不解析 AT。对端不断开则一直留在数据模式。本标准不要求本地逃逸序列。

上电为 AT 模式，不打业务 banner。

---

## 3. UART

| 项 | 标准 |
| --- | --- |
| 物理 | 115200 8N1，无流控 |
| AT 模式 主机→设备 | 一行一条；行尾 CR / LF / CRLF |
| AT 模式 设备→主机 | 行尾 `\r\n` |
| 回显 | AT 模式 **不 echo** 命令 |
| 数据模式 | 8 位透明，不改字节 |
| 行长 | AT 命令超过实现上限则丢弃至换行，不执行 |

---

## 4. AT（仅 AT 模式）

失败一律 `\r\nERROR\r\n`，禁止无限等。超时：关联 **12s**，TCP 建连 **4s**。

| 命令 | 作用 |
| --- | --- |
| `AT` | 探活 → `OK` |
| `AT+GMR` | 见 §4.1 |
| `AT+CWJAP="ssid","pwd"` | 关联 STA；成功：`WIFI CONNECTED`、`WIFI GOT IP`、`OK` |
| `AT+CIPSERVER="host",port` | 写入对端。`host` 为 IPv4 点分十进制；`port` 为 1–65535。成功：`OK`。不建连 |
| `AT+CIPSERVER?` | 读回当前对端。已配置：`+CIPSERVER:"<host>",<port>` 然后 `OK`。未配置：`ERROR` |
| `AT+CONNECT` | 用**当前** `CIPSERVER` 建 TCP。成功见 §4.2。无配置、未关联、建连失败 → `ERROR`，仍留 AT 模式 |

`AT+CIPSERVER` 覆盖上次配置。掉电可丢失（不测持久化）。

### 4.1 `AT+GMR`

允许前导 `\r\n`。三行锁定：

```
TTerm-Demo AT 1.0
ESP32 Arduino
OK
```

### 4.2 `AT+CONNECT`

1. 无有效 `CIPSERVER` 或 STA 未关联 → `ERROR`，不进入数据模式
2. 断开本机已有 TCP（若有）
3. 连接 `CIPSERVER` 的 host:port；失败 → `ERROR`
4. 输出 `CONNECT`（允许其后仅 `\r\n`，不要再跟业务正文）
5. **立即进入数据模式**

对端主动关闭（FIN/RST 或等价）：

1. 停止转发
2. 输出 `CLOSED`
3. 回到 AT 模式（此后 `AT` 必须再应答 `OK`）

---

## 5. 对端 TCP 服务

任意 telnet 式监听即可（收字节、发字节、由服务端关连接）。

验收用服务须能：

| 项 | 标准 |
| --- | --- |
| 绑定 | 服务机 `0.0.0.0` + 测试选用的端口 |
| 语义 | 接受后保持连接，直到测试关闭或它主动断开 |
| 下行 | 可先发一段已知 UTF-8 再保持（便于 S1 看见转发） |
| 上行 | 把收到的字节可观测（回显或日志） |
| 断联 | 服务端 `close` 后，设备必须走 §4.2 离开数据模式 |

---

## 6. 参考命令序

配置与建连（主机发送）：

```
AT+CWJAP="TTerm-Demo","demo-ok-ok"
AT+CIPSERVER="192.168.0.2",23
AT+CONNECT
```

`192.168.0.2` 与 `23` 换成服务机实际 IPv4 与端口。SSID/密码换成测试热点。

成功 UART 子串顺序（设备输出，不含主机本地回显）：

```
WIFI CONNECTED
WIFI GOT IP
OK
OK
CONNECT
```

（`CWJAP` 与 `CIPSERVER` 各一段 `OK`。）进入数据模式后出现对端下行字节。对端关闭后出现 `CLOSED`，再发 `AT` 得 `OK`。

## 7. 验收

全部通过才算达标。

### S0 对端服务（无设备）

| ID | 操作 | 通过 |
| --- | --- | --- |
| S0.1 | 启动监听 | 本机可对约定端口 `connect` |
| S0.2 | 客户端收发若干字节后由服务端断开 | 客户端读到下行；断开可被客户端感知 |

### S1 固件 + 串口监视器

115200，发送 CR+LF。同一 COM 只被监视器打开。先开对端服务。

| ID | 操作 | 通过 |
| --- | --- | --- |
| S1.1 | `AT` | `OK` |
| S1.2 | `AT+GMR` | §4.1 |
| S1.3 | `AT+CIPSERVER?`（未写过） | `ERROR` |
| S1.4 | `AT+CONNECT`（未配置或未关联） | `ERROR`，仍可 `AT` |
| S1.5 | `AT+CWJAP=...` | `WIFI GOT IP`、`OK` |
| S1.6 | `AT+CIPSERVER="…",port` 再 `AT+CIPSERVER?` | 读回与写入一致、`OK` |
| S1.7 | `AT+CONNECT` | `CONNECT`，随后 UART 出现对端下行（若服务有发） |
| S1.8 | 数据模式再发 `AT` | 对端收到字节 `AT`（或 `AT`+换行），设备**不**按 AT 应答 `OK` |
| S1.9 | 服务端断开 | UART 出现 `CLOSED`；再 `AT` → `OK` |
| S1.10 | 再 `AT+CONNECT` | 再次 `CONNECT`，不卡死 |
| S1.11 | 停掉服务后 `AT+CONNECT` | `ERROR` |
| S1.12 | `AT+FOO` | `ERROR` |
| S1.13 | 不 echo | 设备输出不含把刚收到的 AT 命令再打一遍 |

### S2 联程

| ID | 操作 | 通过 |
| --- | --- | --- |
| S2.1 | 复位后按 §6 配网、配地址、`AT+CONNECT` | 8s 内能进数据模式（含关联时间则放宽到关联超时内） |
| S2.2 | 只改 AT 里的 host/port，不重烧 | 连到新对端 |
| S2.3 | 对端断联后改 `CIPSERVER` 再 `AT+CONNECT` | 连到新地址 |

---

## 8. 运行约束

- 测试热点口令仅用于实验，不当正式密钥。
- 服务机须放行入站端口。
- 关联失败属环境，失败路径仍须 `ERROR`。
