# 串口换行（Newlines）配置评估

状态：**O1 已实现**（输出七档：Keep + 六选项，Rust 泵线程状态机，`docs/serial-newlines.md` 为设计依据）；O2（Enter 键换行）O3（粘贴 strip）待排期
日期：2025-07-23

## 背景原理

终端的行控制是**两个独立动作**：

| 字符 | 名称 | 动作 |
|---|---|---|
| `CR` (`\r`, 0x0D) | Carriage Return | 光标回到**列 0**（不换行） |
| `LF` (`\n`, 0x0A) | Line Feed | 光标**下移一行**（不回列 0） |

xterm.js 严格遵循此语义。串口设备的行尾习惯却各不相同：

| 设备发出的行尾 | 现象（无处理时） | 典型设备 |
|---|---|---|
| `CRLF` | ✅ 正常 | 多数 MCU 固件（Arduino、ESP32 例程）、AT 指令设备 |
| 仅 `LF` | ❌ **阶梯状**右移：换行了但不回列 | Unix 风格固件、部分 Linux 控制台 |
| 仅 `CR` | ❌ **行覆盖**：回列了但不下移，后行盖前行 | 老式设备、部分 bootloader/BIOS 串口输出 |
| 混合/不一致 | 间歇性错位 | 多源日志、协议拼接固件 |

## 输出方向选项（设备 → 终端）评估

> 命名与 PuTTY/Tabby 对齐。本质都是对输出流的**换行重写规则**。

### 1. Implicit CR in every LF（每个 LF 隐含 CR）
- **规则**：`LF → CRLF`
- **场景**：设备只发 LF（阶梯文本的解药）。Unix 终端驱动的 `ONLCR` 选项就是这个，Linux 控制台默认开启
- **评价**：**最常用、最该优先实现**的选项；对 CRLF 设备无副作用（`CRLF → CR+CRLF`？——注意：若朴素替换会多一个 CR，正确实现需识别 `CRLF` 已配对序列，见"实现要点"）

### 2. Implicit LF in every CR（每个 CR 隐含 LF）
- **规则**：`CR → CRLF`
- **场景**：设备只发 CR（行覆盖的解药），老式设备/bootloader
- **评价**：与 #1 互为镜像，PuTTY 同款复选；需求频率低于 #1

### 3. Force CRLF（强制 CRLF）
- **规则**：所有行尾（孤 CR / 孤 LF / CRLF）统一改写为 CRLF
- **场景**：行尾不一致的设备（多源日志输出）
- **评价**：= #1 + #2 的并集且去重，语义最"重"但结果最整齐

### 4. Force LF（强制 LF）
- **规则**：所有行尾统一改写为 LF
- **场景**：终端同时承担**日志落盘**职能且下游工具链是 Unix（grep/awk 按 LF 分行）；屏幕上对孤 CR 设备反而引入阶梯
- **评价**：偏记录/管道场景，显示场景少用

### 5. Force CR（强制 CR）
- **规则**：所有行尾统一改写为 CR
- **场景**：极个别老式/专用设备协议
- **评价**：几乎纯兼容性兜底，优先级最低

### 6. Strip（剥离）
- **规则**：移除输出中的 CR/LF 字符
- **场景**：① 单行协议设备（传感器周期输出，只要最新值刷屏覆盖即可配合 CR 归位）；② 类二进制数据流中 CR/LF 是**数据**而非行尾，避免污染显示
- **评价**：小众但有真实用途（与 HEX 视图需求相邻）

## 输入方向选项（终端 → 设备）评估

Tabby 同时提供输入换行配置，虽然你列的六项偏输出，输入侧同样值得登记：

| 选项 | 规则 | 场景 |
|---|---|---|
| Enter = CR | 回车发 `\r` | 绝大多数串口 shell/MCU（事实标准，当前行为） |
| Enter = LF | 回车发 `\n` | Unix 风格固件命令行 |
| Enter = CRLF | 回车发 `\r\n` | 部分 AT 指令/ modem 类设备严格要求 |
| Strip（粘贴时） | 粘贴内容去除换行 | 单行协议设备，防误触多行发送（与多行粘贴警告互补） |

## 实现要点（供后续需求参考）

1. **跨块配对**：串口数据按块到达，`\r` 和 `\n` 可能分处两块边界。重写必须带 1 字节状态机（hold 末尾的 CR 等待下一块判定），否则 Force/Implicit 规则在边界处出错。**这是实现里唯一真正难的点**，必须配套边界测试
2. **改写位置**：后端泵线程（Rust，逐字节状态机，零分配）优于前端——前端输出路径是 AttachAddon 直通，拦截要再开一个旁路
3. **转义序列安全**：CSI/OSC 序列内部通常不含裸 CR/LF，朴素状态机不会误伤；但 OSC 字符串（如标题）含换行时会被改写——风险可接受，文档注明
4. **配置层级**：与现有 `serialPortParams` 一致——全局默认 + 每端口（VID:PID）覆盖；Line by Line 输入模式的行尾符（`\r` vs `\r\n`）应与"Enter 键输入换行"选项联动
5. **默认值建议**：输出 = Raw（不处理，保持当前行为）；Enter = CR。避免破坏已验证设备（FT232、debug probe）
