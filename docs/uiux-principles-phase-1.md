# TTerm UI/UX 交互原则与第一阶段方案

> 状态：方案已确认，第一阶段实现与复审完成，待最终提交。

## 1. 设计目标

TTerm 是与 CLI Agent 结合使用的 Windows 开发终端。交互设计首先保障开发过程的连续性、状态可理解性和操作可控性，再追求功能数量与视觉装饰。

统一交互应服务三类开发上下文：

1. 本地 Shell 与 CLI Agent；
2. SSH 远程开发；
3. 串口与设备调试。

三类会话可以拥有不同的专业控制，但应共享相同的基础行为：创建、切换、状态表达、菜单操作、反馈、关闭和恢复。

---

## 2. 统一 UI/UX 原则

### UX-01｜开发流优先

终端输入焦点、键盘操作和连续输出是核心工作流。非必要界面不应抢焦点、遮挡终端或用模态窗口打断操作。

例外：安全授权、不可逆操作、覆盖外部配置和可能向真实设备产生高影响的操作。

### UX-02｜所有能力先有可见路径，快捷方式只负责加速

Shift+点击、右键、快捷键可以保留，但不能成为某项能力的唯一入口。用户应能从可见界面找到同一操作。

### UX-03｜状态靠近对象，并同时使用文字、图形与颜色

会话状态应优先显示在对应标签或会话面板上。颜色只用于强化，不单独承担含义。

连接状态、AI 分享授权、后台活动和错误是不同维度，不应强行压缩成一个互斥状态。

### UX-04｜同一动作具有同一结果

无论操作来自按钮、右键菜单还是快捷键，都应经过同一业务入口，产生一致的确认、反馈、错误处理和焦点恢复。

### UX-05｜即时操作即时生效，延迟提交必须明确

主题、字体等普通偏好倾向即时预览和保存。覆盖 `~/.ssh/config`、创建分享授权等具有外部影响的操作应明确展示提交边界。

界面不得让用户猜测“当前只是预览、已经应用，还是已经写入磁盘”。

### UX-06｜错误需要解释状态和下一步

错误反馈至少回答：发生了什么、当前会话是否仍安全、用户下一步能做什么。短暂成功提示可以使用 Toast，持续异常必须留在相关会话附近。

### UX-07｜键盘是第一等输入方式

主要功能必须可通过键盘完成。自定义菜单遵循统一的打开、方向键移动、Enter/Space 激活、Escape 关闭和焦点返回规则，并使用正确的控件语义。

### UX-08｜中文是第一产品语言

新增用户文案先完成中文定义，再提供英文版本。术语在产品内保持一致；CLI、Shell、SSH、Agent 等行业术语可以保留英文，但动作和风险说明优先使用自然中文。

### UX-09｜专业能力渐进呈现

默认界面只展示高频动作。端口转发、流控、RTS/DTR 等专业控制在对应会话上下文中出现，不占用所有用户的主界面注意力。

### UX-10｜授权持续可见、随时可撤销

AI 能看到什么、能控制什么必须在授权前说明，并在授权期间持续可见。停止分享或收回控制权限始终是直接操作。

### UX-11｜不破坏已有专家效率

统一入口和可发现性改进不能删除已有快捷方式。涉及终端焦点、IME、滚动和渲染的改动必须进行专门回归。

### UX-12｜小步改变，以行为验收

每一阶段聚焦一组可以独立验证的行为，不同时进行信息架构、视觉风格和底层状态模型的大重构。

## 3. 第一阶段目标

第一阶段名称：**基础交互一致性清理**。

目标是在不改变核心业务流程和视觉布局的前提下，统一弹出菜单、按钮、键盘操作、焦点和基础可访问性，为后续的新建入口、分享授权与状态系统重构建立可靠基础。

### 选择这一阶段的原因

- 改动范围小，主要发生在前端交互层；
- 不需要修改 Rust 后端、协议或持久化数据；
- 用户可立即感知键盘操作和控件反馈改善；
- 能提前形成后续所有菜单和选择器应复用的交互规则；
- 可以通过单元测试和现有 E2E 明确回归。

---

## 4. 第一阶段实施范围

### P1-01｜统一可点击元素语义

将下列使用 `div + click` 模拟的交互元素改为原生 `button`，或在确实不能使用按钮时补齐等价语义：

- 新建会话菜单中的 Local、SSH、Serial 条目；
- 标签右键菜单与终端右键菜单中的动作条目；
- 标签颜色选择和重置入口；
- 其他本轮触达模块中同类型的简单动作控件。

要求：

- 不改变现有视觉尺寸和排列；
- 清除原生按钮默认边框、背景和字体差异；
- 禁用态必须使用真实 `disabled`；
- 不将纯展示元素错误改造成可交互控件。

### P1-02｜统一弹出菜单键盘模型

新建会话菜单和右键菜单统一支持：

- 打开后焦点进入第一个可用条目；
- `ArrowUp` / `ArrowDown` 在当前菜单条目间移动；
- `Home` / `End` 移动到首尾；
- `Enter` 或 `Space` 执行当前条目；
- `Escape` 关闭菜单；
- 关闭后焦点返回触发按钮或原来的终端/标签；
- 鼠标点击菜单外仍保持现有关闭行为。

本阶段不实现模糊搜索，也不把三列新建菜单重构为命令面板。

### P1-03｜补齐按钮名称和动态说明

补齐或修正以下控件的 `aria-label` / `title`：

- 默认新建标签按钮；
- 搜索栏的上一个、下一个和关闭按钮；
- 设置伪标签的关闭按钮；
- 标签关闭按钮；
- 快捷状态按钮。

快捷状态按钮的说明随活动会话变化，至少能表达：

- 当前没有可操作会话；
- 会话已连接；
- 会话已断开；
- 会话正在分享给 AI。

本阶段不改变红点/蓝点的视觉状态模型。

### P1-04｜统一弹层关闭与焦点恢复

对本轮涉及的菜单建立同一行为：

- `Escape` 只关闭最上层弹层，不触发终端输入；
- 点击外部关闭；
- 窗口尺寸变化时，菜单重新定位或安全关闭；
- 菜单执行动作后关闭；
- 关闭后恢复合理焦点，不让键盘焦点落到 `body`。

颜色子菜单继续保留当前视觉形式，但必须能够通过键盘打开、选择和返回父菜单。

### P1-05｜建立共享菜单交互辅助层

只提取本阶段真正重复的行为，例如：

- 获取可用菜单项；
- 焦点循环/边界移动；
- Escape 关闭与焦点恢复；
- 标准菜单键盘事件。

不在第一阶段创建大型 UI 框架，也不强制一次迁移所有弹窗、选择器和设置控件。

---

## 5. 第一阶段明确不做

以下问题重要，但不与基础清理混在同一批实现：

- 首次启动页与新用户引导；
- 新建会话命令面板和搜索；
- 中文/英文 i18n 架构及全量文案迁移；
- AI 分享的只读/可控制授权对话框；
- 分享链接生命周期和 Agent 操作审计；
- 会话状态拆分、后台活动和任务完成检测；
- 设置保存模型及未保存关闭确认；
- 统一 Session Close Guard、进程树风险判断及活动连接关闭确认；
- SSH/串口重连状态模型；
- 标签分组、工作区与会话恢复；
- 整体视觉主题、布局或组件库重构。

这些内容在第一阶段完成后，依据产品评审表的批注确定后续顺序。

- 不重写现有菜单的业务动作分发逻辑。

## 7. 验收标准

### 行为验收

1. 新建会话菜单可以全程只用键盘选择 Local、SSH 或 Serial 会话。
2. 标签右键菜单打开后可以用键盘选择并执行动作。
3. 颜色子菜单可以用键盘进入、选择颜色、重置和返回。
4. 所有菜单都能通过 Escape 关闭，且不会把 Escape 发送到终端。
5. 菜单关闭后焦点回到合理触发位置，终端可继续输入。
6. 图标按钮具备明确可读名称，动态状态说明与实际状态一致。
7. 鼠标行为、菜单位置、标签操作和现有快捷键不发生回归。

### 工程验收

1. `bun run lint` 通过；
2. `bun test` 通过；
3. `bun run build` 通过；
4. 与菜单、快捷键、标签、快速面板相关的 E2E 通过；
5. `git diff --check` 通过；
6. 不包含未批准的视觉重构、文案翻译或业务行为变化。

### 人工验收

在 Windows 应用中至少验证：

- 鼠标与键盘分别打开和操作新建菜单；
- 标签右键菜单及颜色子菜单；
- 搜索栏按钮名称与焦点；
- 设置标签和普通标签关闭；
- 快捷状态按钮在普通、分享、断开状态下的说明；
- 关闭菜单后中文 IME 与终端输入焦点不受影响。
